# Deploying hiriketiyanoahsurfschool.com (VPS + nginx + Cloudflare)

Architecture:

```
Browser → Cloudflare (proxy, HTTPS) → VPS nginx :443 (Origin cert)
                                        ├── /            → Next.js  127.0.0.1:3000 (pm2: surfsite-web)
                                        └── /api,/uploads,/health → Express 127.0.0.1:5000 (pm2: surfsite-api)
                                                                      └── MongoDB Atlas
```

The current **522 error** = Cloudflare reaches your DNS record but nothing answers
on the VPS. Steps 1–6 below fix that.

---

## Step 1 — Cloudflare DNS

Cloudflare dashboard → your domain → **DNS → Records**:

| Type  | Name | Content        | Proxy |
|-------|------|----------------|-------|
| A     | `@`  | `YOUR_VPS_IP`  | 🟠 Proxied |
| CNAME | `www`| `hiriketiyanoahsurfschool.com` | 🟠 Proxied |

Delete any other A/AAAA records pointing elsewhere.

## Step 2 — One-time VPS setup

SSH into the VPS, then:

```bash
ssh root@YOUR_VPS_IP
git clone https://github.com/Izu99/surfsite.git /var/www/surfsite
bash /var/www/surfsite/deploy/01-setup-vps.sh
```

This installs Node 22, nginx, pm2, fail2ban, adds swap if RAM is low,
installs the nginx site config, and creates the env files.

## Step 3 — Edit the server env

```bash
nano /var/www/surfsite/server/.env
```

- Set `MONGO_URI` — create a **new** Atlas database user for production
  (don't reuse the dev `lms/lms123` user), and in Atlas → **Network Access**
  add your VPS IP to the allowlist.
- `JWT_SECRET` was auto-generated by the setup script — leave it.
- `CLIENT_URL` must stay `https://hiriketiyanoahsurfschool.com` (used for CORS).

## Step 4 — Cloudflare Origin Certificate (for HTTPS between Cloudflare and VPS)

1. Cloudflare dashboard → **SSL/TLS → Origin Server → Create Certificate**
2. Keep defaults (RSA, `*.hiriketiyanoahsurfschool.com` + apex, 15 years) → Create
3. Copy the two blocks onto the VPS:

```bash
nano /etc/ssl/cloudflare/hiriketiyanoahsurfschool.com.pem   # paste "Origin Certificate"
nano /etc/ssl/cloudflare/hiriketiyanoahsurfschool.com.key   # paste "Private Key"
chmod 600 /etc/ssl/cloudflare/hiriketiyanoahsurfschool.com.key
nginx -t && systemctl reload nginx
```

4. Cloudflare → **SSL/TLS → Overview** → set mode to **Full (strict)**.
   (Never use "Flexible" — it causes redirect loops and is insecure.)

## Step 5 — Build & run everything

```bash
bash /var/www/surfsite/deploy/deploy.sh
```

This pulls latest `main`, builds server + client, starts both under pm2
(auto-restart + start on boot), reloads nginx, and runs health checks.
**Re-run this same script for every future update** — that's the whole
deploy process from now on.

## Step 6 — Firewall (block unnecessary ports)

```bash
bash /var/www/surfsite/deploy/02-firewall-cloudflare.sh
```

After this:
- **Everything is blocked by default** — ports 3000, 5000, MongoDB, etc. are unreachable from outside.
- Port 22 (SSH) is open.
- Ports 80/443 accept traffic **only from Cloudflare IP ranges**, so the site
  can't be accessed by IP directly (attackers can't bypass Cloudflare or
  discover your origin IP via scanning).

Check anytime with: `ufw status verbose`

## Step 7 — Cloudflare security settings (dashboard)

Do these once in the Cloudflare dashboard:

| Where | Setting | Value |
|---|---|---|
| SSL/TLS → Overview | Encryption mode | **Full (strict)** |
| SSL/TLS → Edge Certificates | Always Use HTTPS | **On** |
| SSL/TLS → Edge Certificates | Minimum TLS Version | **TLS 1.2** |
| SSL/TLS → Edge Certificates | TLS 1.3 | **On** |
| SSL/TLS → Edge Certificates | Automatic HTTPS Rewrites | **On** |
| Security → Bots | Bot Fight Mode | **On** |
| Security → Settings | Security Level | **Medium** |
| Security → Settings | Browser Integrity Check | **On** |
| Speed → Optimization | Brotli | **On** |

Optional (free plan includes 1 rate-limiting rule):
**Security → WAF → Rate limiting rules** → create a rule:
- If URI Path starts with `/api/auth` → more than 10 requests per 1 minute → Block.
  (The API also rate-limits internally, but this stops floods at the edge.)

Note: Cloudflare's proxy only forwards standard web ports anyway; the real
port-blocking happens on the VPS via Step 6.

## Step 8 — Verify

```bash
curl -I https://hiriketiyanoahsurfschool.com          # 200, from anywhere
curl -I https://hiriketiyanoahsurfschool.com/health   # API health via nginx
curl -I http://YOUR_VPS_IP                            # should TIME OUT (firewall works)
```

On the VPS: `pm2 status`, `pm2 logs`, `systemctl status nginx`.

## Security checklist / hardening notes

- [ ] **Rotate exposed dev credentials.** The local dev `server/.env` contains a
      real Atlas password, a Gmail app password, and a Firebase private key.
      It was never committed to git, but treat dev secrets as dev-only:
      create separate production credentials and revoke anything shared outside your machine.
- [ ] **SSH keys instead of passwords.** After confirming key login works:
      `nano /etc/ssh/sshd_config` → `PasswordAuthentication no`, `PermitRootLogin prohibit-password` → `systemctl restart ssh`
- [ ] fail2ban is enabled by the setup script (bans brute-force SSH attempts).
- [ ] Automatic security updates are enabled (`unattended-upgrades`).
- [ ] Cloudflare IP ranges change rarely; refresh firewall rules occasionally by
      re-running `02-firewall-cloudflare.sh`.

## Common issues

| Symptom | Fix |
|---|---|
| 522 again | `pm2 status` — apps running? `ufw status` — Cloudflare ranges allowed? DNS A record = correct VPS IP? |
| 521 | nginx down or cert missing: `nginx -t && systemctl restart nginx` |
| Redirect loop | SSL mode is "Flexible" — switch to **Full (strict)** |
| API calls fail in browser | `client/.env.production` wrong at build time — fix and re-run `deploy.sh` |
| Next.js build killed | Out of memory — setup script adds swap; check `free -h` |
